1. Qué es New Relic y qué se probó

New Relic es una plataforma de observabilidad en la nube: recibe en tiempo real los datos internos de una aplicación (qué peticiones atiende, cuánto tardan, si fallan, cuánta memoria usa…) y los muestra en paneles con búsquedas (NRQL) y alertas. La prueba comprueba que CyberShield envía los tres pilares de la observabilidad:

PilarQué esQué envía CyberShield
TrazasEl recorrido de cada petición dentro del servidor, con su duración.Una traza por petición, nombrada por ruta (GET /, POST /…), con código de estado, duración, X-Request-Id y un evento cuando el limitador rechaza una petición.
MétricasNúmeros medidos cada cierto tiempo.7 métricas: duración de las peticiones, event loop, memoria, peticiones en curso y rechazos del limitador.
LogsEl registro escrito de lo que pasa.Un log por petición (INFO, y WARN para 404, 405 y 429), enlazado con su traza: desde un log se salta a la traza y al revés.

2. Cómo se hizo la prueba

k6 (50 estudiantes simulados) │ peticiones HTTP ▼ Servidor CyberShield + OpenTelemetry (observabilidad/newrelic/telemetria.js, cargado con node -r) │ OTLP/HTTP · cabecera api-key · temporalidad DELTA (en New Relic: https://otlp.nr-data.net) ▼ Receptor OTLP local que imita a New Relic → resumen de trazas, métricas y logs → este informe

Se usa OpenTelemetry, el estándar abierto de observabilidad que New Relic recomienda. Con la clave válida, basta con definir NEW_RELIC_LICENSE_KEY para que los mismos datos lleguen a New Relic. El código no cambia.

8. Problemas encontrados

  • Dos errores de integración, detectados y corregidos por la verificación antes de usar la cuenta: en el SDK 3.x de OpenTelemetry los procesadores por lotes se construyen ahora con { exporter }, y el paquete protobuf no exporta la constante de temporalidad. Sin la corrección, el servidor no habría arrancado en modo New Relic.
  • Claves rechazadas por New Relic ("Forbidden" / "authentication required"): ocurrió igual desde la nube y desde el PC del estudiante. Causas probables: la cuenta no tiene el correo verificado o tiene la ingesta desactivada, o la clave se copió incompleta. Para comprobarlo: observabilidad\newrelic\diagnostico.bat (prueba la clave en EE. UU. y Europa). Solución recomendada: copiar la clave desde el instalador guiado (Add data → OpenTelemetry) o crear una cuenta nueva.

9. Glosario

Observabilidad
Capacidad de entender qué pasa dentro de una aplicación mientras funciona, a partir de sus trazas, métricas y logs.
OpenTelemetry (OTel)
Estándar abierto para generar y enviar telemetría. Funciona con New Relic, Grafana, Datadog, Jaeger… cambiando solo el destino.
OTLP
El protocolo de OpenTelemetry para enviar los datos (aquí, HTTP con JSON o protobuf).
Traza (span)
El registro de una petición: nombre, inicio, duración, atributos y eventos. Se identifica con un trace_id.
Logs in context
Logs que llevan el trace_id de la petición que los generó, para saltar del log a la traza y al revés.
p50 / p95 / p99
Percentiles: el 50 %, el 95 % o el 99 % de las peticiones tardó menos que ese valor.
Temporalidad DELTA
Cada envío de métricas contiene solo lo ocurrido desde el envío anterior (la que prefiere New Relic).
NRQL
El lenguaje de consultas de New Relic, parecido a SQL, con el que se construyen gráficos y alertas.
License key / User key
La License key (termina en NRAL) sirve para enviar datos; la User key (NRAK-…) sirve para consultarlos y gestionar dashboards.

10. Cómo repetirlo en New Relic

  1. Comprobar la clave: observabilidad\newrelic\diagnostico.bat.
  2. Ejecutar la prueba: observabilidad\newrelic\ejecutar-newrelic.bat (pide la License key).
  3. Ver en New Relic: APM & Services → cybershield, Traces y Logs.
  4. Importar el dashboard: npm run newrelic:dashboard -- TU_ACCOUNT_ID → Dashboards → Import dashboard.

Reproducir este informe sin cuenta: node observabilidad/newrelic/prueba-k6-local.js y después node observabilidad/newrelic/informe.js.
